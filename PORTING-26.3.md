# Hybrid Aquatic → Minecraft 26.3 / Fabric

**Статус: локальный тестовый порт собирается и проходит серверные и клиентские проверки.**
Это неофициальная сборка `1.7.4-port.4+26.3`; длительное прохождение и совместимость
с произвольными модпаками не проверялись.

## Установка и сборка

Готовый комплект: `build/distributions/hybrid-aquatic-26.3-fabric-port.4.zip`.
Инструкция находится в `PORT-INSTALL.txt`. Архив содержит папку `mods` с Hybrid Aquatic,
перенесённой Hybrid API и точными версиями зависимостей, использованными в тестах.
Требуются Minecraft Java Edition 26.3, Java 25 и Fabric Loader 0.19.5.

```sh
./gradlew portBundle
```

Отдельные файлы:

- `build/libs/hybrid-aquatic-fabric-1.7.4-port.4+26.3.jar`
- `hybrid-api/build/libs/hybrid-api-fabric-1.1.3-port.2+26.3.jar`

Тестовые классы, миры и тестовые ресурсы в эти JAR не входят.

## Названия, подсказки и достижения port.4

Предметы-блоки теперь явно используют ключ перевода своего блока, в том числе
когда ID предмета и блока различаются (например, `clam` / `clams`). Это исправляет
отображение технических ключей вместо названий и подсказок вариантов бутылки.
Клиент добавляет синюю курсивную строку `Hybrid Aquatic` непосредственно под
названием только предметов этого мода. Описания, пользовательские названия
и технические строки расширенных подсказок сохраняются.

В русском языке переведены все 66 строк названий и описаний достижений (32 активных
достижения и пара строк для сачка). Исправлено устаревшее описание получения
акульего зуба: требуется заблокировать атаку щитом. Подсказки плюшевых акул и
вариантов бутылки также переведены. Фон вкладки использует новый формат ID
`hybrid_aquatic:block/coralstone`: Minecraft сам добавляет `textures/` и `.png`.
Исходная текстура сохранена.

Для сборки отдельно от каталогов классов IDE используется
`./gradlew --offline -I tools/port4-build.gradle :build :portBundle`.
Результаты находятся в `build-port4/`; готовые релизные файлы также копируются
в обычные `build/libs/` и `build/distributions/`.

Проверки port.4 прошли: все 523 предмета в английском и русском интерфейсе,
обычные/расширенные подсказки, сохранение пользовательских названий, отсутствие
подписи HA у ванильного предмета. В клиенте проверены 32 активных достижения,
наличие текстуры фона и отрисовка вкладки. Полный клиентский набор и 5 обязательных
серверных тестов прошли. Лог и снимки: `build/reports/porting/port.4/`.

Hybrid API остаётся версии `1.1.3-port.2+26.3`. Для совместного использования с
WWOO нужен патч `wwoo-hybrid-aquatic-compat-1.0.1+26.3.jar`, разрешающий port.3 и
port.4. Генерация мира и параметры существ в этом обновлении не менялись.

## Оптимизации port.3

Обновляются оба мода: Hybrid Aquatic `1.7.4-port.3+26.3` и Hybrid API
`1.1.3-port.2+26.3`. Внешние зависимости прежние; число существ, лимиты спавна,
генерация мира и подводный снег в этом проходе не изменялись.

- `FollowGlowingEntityGoal`: поиск ограничен одним запросом за 10 игровых тиков,
  первые поиски распределены по ID сущностей. Цель объявляет управление `MOVE`,
  поэтому больше не конкурирует одновременно с другими задачами навигации.
  Маршрут обновляется не чаще раза за 10 тиков и только при перемещении цели
  минимум на блок либо завершении/неудаче предыдущего пути. Потеря свечения,
  смерть цели и достижение минимальной дистанции по-прежнему проверяются при
  каждом вызове проверки продолжения цели.
- `PoseContext`: вместо `LinkedHashMap`, его записей и двух массивов на кость
  используется короткий связный список преобразований с числовыми полями.
  Состояние по-прежнему принадлежит отдельному кадру и сущности; оно не разделяется
  между отложенными проходами рендера разных сущностей.
- Десять базовых классов моделей водных существ сохраняют постоянные идентификаторы
  моделей, текстур и анимаций. Выбор детской и взрослой модели сохранён.

Добавлены проверки ограничения частоты поиска и запросов пути, повторного запуска
следования, остановки при потере свечения/сближении, а также композиции преобразований
костей, отсутствующих костей и независимости состояний разных кадров/существ.
Клиентский тест также измеряет выделенные байты на создание позы с пятью костями
через `ThreadMXBean` после прогрева. Это узкий тест выделения памяти, не замер FPS
или полной нагрузки рендера; эффект в пользовательском модпаке требует сравнения
одной сцены до и после обновления.

Измерение на одной JVM-конфигурации Java 25: до изменений **856 байт**, после
**320 байт** на позу с пятью костями (100 000 итераций после 20 000 прогревочных),
то есть на **62,6% меньше** в этом участке. Замер не включает остальные расходы
GeckoLib, отрисовку, GPU и ИИ; переносить этот процент на FPS нельзя.

Проверки port.3 завершились успешно: 5 обязательных серверных тестов Hybrid Aquatic,
4 теста Hybrid API (оба числа включают встроенный тест Fabric), оба клиентских набора
с реальной загрузкой Minecraft, отрисовкой существ и проверкой поз. Просмотрены
снимки рыб и цветового слоя HAPI. Логи до/после:
`build/reports/porting/port.3/allocation-before.log` и
`build/reports/porting/port.3/validation.log`.

## Исправление port.2

Исправлен сбой `Ticking entity / Can't find attribute minecraft:tempt_range`,
обнаруженный при первом тике Sea Bass. В 26.3 `TemptGoal` читает этот атрибут;
исходные наборы атрибутов Hybrid Aquatic начинались с `createLivingAttributes()`
и не включали его. При регистрации всем существам мода теперь задаётся
`TEMPT_RANGE = 10.0`, как у ванильных животных. Остальные характеристики сохранены.
Hybrid API и версии внешних зависимостей для этого исправления не менялись.

Добавлен серверный регрессионный тест `allMobAiTicksInWater`: он запускает
40 тиков каждого моба с включённым ИИ. До исправления тест воспроизвёл
`Can't find attribute minecraft:tempt_range`, после исправления прошёл.
Серверный набор port.2: **5 обязательных тестов успешно**, включая встроенный
тест Fabric. Полный сторонний модпак из присланного отчёта не воспроизводился.

## Изменения

Корневая Fabric-сборка объединяет исходники `common` и `fabric` и подключает локальный
подмодуль через `hybrid-api/port.gradle`. Перенесены регистрации с явными ключами,
сериализация ValueInput/ValueOutput, компоненты предметов, материалы и инструменты,
интерполяция транспорта, поведение существ, взаимодействия, эффекты и сетевые пакеты.

GeckoLib 5 и новый рендер Minecraft используют извлечённое состояние кадра.
Модели, поправки к костям, свечение, цветовые слои и удерживаемые предметы перенесены
в этот процесс. Обновлены камера Argonaut, рыболовные крючки, туман, морской снег,
картины, игрушки на голове, броня, частицы и анимированные блоки.

Ресурсы моделей и анимаций перенесены в `geckolib/`, добавлены определения предметов.
Обновлены форматы рецептов, торговли, варки зелий, достижений, добычи, биомов,
объектов генерации, плотности рельефа и правил поверхности Lithostitched.
Старые случайные растительные пятна выражены через размещения с количеством
попыток и треугольным распределением смещения, сохраняя исходные параметры.

Исправлены найденные ошибки сохранения активности существ, создания добычи
бутылки и сохранения её разновидности. Призыв через раковину ожидает нужный игровой
тик в очереди, вместо повторной постановки задачи без задержки.

## Проверки

Запуск из корня проекта:

```sh
./gradlew build :hapi:build runPortFeatureTest
./gradlew :runGameTest :hapi:runGameTest
SDL_VIDEODRIVER=offscreen ALSOFT_DRIVERS=null ./gradlew :runClientGameTest :hapi:runClientGameTest
```

Основные серверные сценарии:

1. Создание всех типов сущностей Hybrid Aquatic, проверка атрибутов существ,
   сохранение и восстановление через штатный формат 26.3.
2. Заброс удочки с крючком и возврат крючка после сматывания.
3. Сохранение топлива и груза Argonaut, сохранение варианта бутылки при добыче
   инструментом с «Шёлковым касанием».

Тесты Hybrid API отдельно проверяют состояния водного существа и захват сетью.
Проверка кодеков генерации проверяет обратимое кодирование, изоляцию экземпляров
и отклонение недопустимых параметров.

Клиентские сценарии запускают настоящий Minecraft 26.3. Они отрисовывают все типы
существ и страницы предметов, перебирают экипировку, показывают анимированные
блоки, создают обычный мир с генератором шума и находят траншейный биом.
Проверяются также дождь и эффект ясности под водой. Скриншоты сохраняются в
`build/run/clientGameTest/screenshots/`; отдельный тест библиотеки проверяет
цветовой слой и удерживаемый предмет на модели рыбы.

Полный прогон port.1 завершился успешно: основной сервер — 4 теста,
сервер библиотеки — 3 теста (в каждом числе есть встроенный тест Fabric),
проверки кодеков и оба клиентских набора. При визуальном просмотре исправлено
положение игрушки на голове, затем повторён основной клиентский набор.

## Границы этой сборки

- Поддерживается Fabric 26.3. NeoForge в корневую сборку не входит.
- Старые генераторы данных не компилируются: сборка использует перенесённые
  JSON в `common/src/main/resources` и `fabric/src/generated/resources`.
- Автоматические проверки не заменяют длительную игру, проверку каждого варианта
  существа и комбинаций сторонних модов. Старый мир следует проверять на копии.
- В окружении без окна и звукового устройства Minecraft сообщает об отсутствии
  системного синтезатора речи и некоторых графических настройках. Это не мешает
  завершению клиентских тестов; отсутствующих моделей и текстур в финальной
  загрузке ресурсов не обнаружено.
